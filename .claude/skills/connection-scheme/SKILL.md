# Схемы подключения moduleBox

Схема подключения — это SVG с фиксированной раскладкой (контроллер справа,
устройства слева, нумерованные жгуты). Она **генерируется** из YAML-описания
скриптом `tools/scheme_gen/generate.py` — рисовать SVG вручную нельзя.

## Архитектура

- `tools/scheme_gen/generate.py` — генератор YAML → SVG (`--pdf` → ещё и PDF).
- `tools/scheme_gen/from_config.py` — `config.ini` контроллера → YAML.
- `tools/scheme_gen/build.py` — конвейер config → YAML → SVG → PDF для папки.
- `tools/scheme_gen/README.md` — **полная спецификация формата YAML** и правила
  разбора config.ini. Прочитать перед заполнением описания.
- `loads.yaml` (в этой папке) — **база нагрузок**: пины аппаратных модулей,
  таблица `mode → железо`, типы нагрузок и шаблоны их проводки, флаги.
  Новый тип нагрузки / модуль / флаг добавляется сюда, не в код.
- `content/.../_assets/<модуль>.scheme.yaml` — описание схемы (исходник).
- `content/.../_assets/<модуль>.svg` — сгенерированная картинка, встраивается
  в страницу через `![[.../_assets/<модуль>.svg]]`.

YAML лежит рядом с SVG, имя совпадает: `stepper.scheme.yaml` → `stepper.svg`.

Два сценария:
1. **Схема модуля для wiki** — YAML пишется руками (ниже, «Рабочий процесс»).
2. **Схема контроллера проекта** — из `config.ini` в `schemes_workspace/`
   (раздел «Проектные схемы из config.ini»).

## Рабочий процесс

1. **Прочитать** `tools/scheme_gen/README.md` — формат YAML и адресацию пинов.
2. **Найти/создать** `_assets/<модуль>.scheme.yaml`:
   - если схема уже есть — взять существующий YAML;
   - если есть только старый `.svg` (draw.io) — открыть его как картинку
     (отрендерить, см. ниже) и перенести структуру в YAML вручную;
   - новый модуль — взять структуру из страницы модуля и прошивки.
3. **Заполнить YAML.** Состав модулей, имена и порядок пинов, цвета проводов —
   сверять с реальной прошивкой/железом, не выдумывать. Где данных нет —
   заполнить правдоподобно и явно сказать пользователю, что это требует сверки.
4. **Сгенерировать:**
   ```sh
   python tools/scheme_gen/generate.py "content/.../_assets/<модуль>.scheme.yaml" -o tmp/preview.svg
   ```
   Сначала в `tmp/` — пока пользователь не утвердил, рабочий `.svg` не трогать.
5. **Показать превью** пользователю (см. рендеринг ниже) и **итерировать**:
   правка YAML → перегенерация → показ. Структура одинакова для всех схем —
   меняется только YAML.
6. **Финализировать** после одобрения: при замене существующего `.svg` сделать
   бэкап старого в `hlam/`, скопировать `tmp/preview.svg` в `_assets/<модуль>.svg`.
   Если страница модуля ещё не встраивает картинку — добавить
   `![[.../_assets/<модуль>.svg]]` в раздел «Пример подключения».

## Проектные схемы из config.ini

Раскладка папок: `schemes_workspace/<Проект>/<контроллер>/config.ini` →
рядом появятся `<deviceName>.scheme.yaml`, `.svg`, `.pdf`. Папка в git —
готовые проекты служат образцами.

1. Пользователь присылает `config.ini` (или путь к нему). Положить его в
   `schemes_workspace/<Проект>/<контроллер>/config.ini` (имя контроллера =
   `deviceName`). Если проект не назван — спросить.
2. Проверить комментарии слотов: тип нагрузки должен быть в `loads.yaml`.
   Грамматика — `;<тип>[_xN] [подпись] [флаги]`, см. README генератора.
   Неизвестный тип / mode → предупреждение в stderr, нагрузка пропускается —
   тогда либо добавить тип в `loads.yaml`, либо уточнить у пользователя.
3. Собрать: `python tools/scheme_gen/build.py "schemes_workspace/<Проект>/<контроллер>"`.
   Существующий YAML **не пересоздаётся** (в нём ручные правки); пересоздать
   после изменения config.ini — `--force`, предварительно перенеся правки.
4. Показать превью (ниже), проверить: все слоты из конфига на месте, подписи
   crosslink на нужных датчиках, нет «тонких» жгутов (жгут связывает больше
   двух блоков — разбить шаблон в `loads.yaml`).
5. Ручные уточнения (артикулы БП, цвета проводов, доп. блоки) — правкой
   `<deviceName>.scheme.yaml`, затем `build.py` без `--force`.

Пины модулей в `loads.yaml`, помеченные «СВЕРИТЬ», взяты из старых картинок и
не подтверждены по железу — предупреждать пользователя, если такой модуль
попал на схему.

## Рендеринг превью (для визуальной проверки)

Quartz рендерит SVG сам, но чтобы *увидеть* результат, отрендерить SVG в PNG
через headless-браузер и открыть PNG как изображение. На Windows:

```sh
"C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" --headless=new \
  --disable-gpu --hide-scrollbars --default-background-color=FFFFFFFF \
  "--screenshot=<абс.путь>\preview.png" --window-size=<W>,<H> "<абс.путь>\preview.svg"
```

`W`/`H` — из атрибутов `width`/`height` сгенерированного SVG. Пути — абсолютные.

## Правила

- **Раскладку не менять руками** — она зашита в генератор; правки только в YAML
  или, при общем изменении стиля, в `generate.py` (тогда перегенерировать все
  затронутые схемы).
- Цвет провода в YAML задаётся один раз → на обоих концах жгута совпадает
  автоматически. Не дублировать цвет.
- Имена пинов в `pins` и в адресах `wires` должны совпадать посимвольно
  (учитывая регистр). Переименовал пин — обнови все ссылки в жгутах.
- Пользователь часто правит `.scheme.yaml` сам между итерациями — перечитывать
  файл перед изменениями.
