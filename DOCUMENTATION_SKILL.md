# DOCUMENTATION SKILL - Правила оформления документации moduleBox

Документ описывает стандарты оформления документации программных и аппаратных модулей для wiki проекта moduleBox на основе анализа актуальных страниц документации.

---

## 1. ОБЩИЕ ПРИНЦИПЫ

### 1.1 Формат файлов
- Все файлы документации в формате **Markdown** (.md)
- Движок — **Quartz** (статический генератор на базе Hugo)
- Поддерживается синтаксис **Obsidian** (wikilinks `[[]]`, callout-блоки, embeds `![[]]`)

### 1.2 Расположение файлов
```
mbWiki/content/
  ├── Программные модули/
  │   ├── moduleName_sw.md          # Документация программного модуля
  │   └── _assets/                   # Изображения и медиа
  ├── Аппаратные модули/
  │   ├── moduleName_hw.md          # Документация аппаратного модуля
  │   └── _assets/                   # Изображения и медиа
  ├── Устройства/
  └── Платформа moduleBox/
```

### 1.3 Именование файлов
- Программные модули: `{moduleName}_sw.md`
- Аппаратные модули: `{moduleName}_hw.md`
- Имя файла совпадает с именем mode в конфигурации

### 1.4 Язык
- Документация пишется на **русском** языке
- Технические термины (имена опций, команд, топиков) остаются на **английском**
- Примеры кода и конфигурации на **английском**

## 3. FRONTMATTER (YAML-заголовок)

### 3.1 Формат

```yaml
---
title: Название на русском языке
draft: false
tags:
  - тег1
  - тег2
---
```

### 3.2 Правила
- **title** — обязательное, краткое название модуля на русском
- **draft** — `false` для опубликованных, `true` для черновиков
- **tags** — необязательное, теги для категоризации

### 3.3 Типичные теги
| Тег | Назначение |
|-----|-----------|
| `sw` | Программный модуль |
| `hw` | Аппаратный модуль |
| `input` | Модуль с входными данными |
| `output` | Модуль с выходными данными |
| `trigger` | Дискретный датчик |
| `distance` | Датчик расстояния |
| `uart` | Использует UART |
| `smartLed` | Адресные светодиоды |
| `led` | Светодиоды |
| `button` | Кнопка |
| `sound` | Звук |
| `player` | Проигрыватель |

## 4. БЛОК MODE

### 4.1 Формат
Сразу после frontmatter, перед описанием:

````markdown
```
[SLOT_n]
mode = имя_модуля
```
````

### 4.2 Правила
- Имя модуля **точно совпадает** с именем в конфигурации устройства
- Если модуль привязан к конкретному слоту, указать номер: `[SLOT_0]; только для нулевого слота`
- Если подходит любой слот — `[SLOT_n]`

### 4.3 Примеры

```markdown
[SLOT_n]
mode = button_led
```

```markdown
[SLOT_0]; только для нулевого слота
mode = mp3Player
```

## 6. РАЗДЕЛ «ТОПИКИ»

### 6.1 Формат

```markdown
## Топики
Стандартный топик события:
- *"deviceName/{префикс}_{slot_num}"* - {slot_num} номер слота
	- пример: "deviceName/{префикс}_0"

Стандартный топик действия:
- *"deviceName/{префикс}_{slot_num}"* - {slot_num} номер слота
	- пример: "deviceName/{префикс}_0"
```

### 6.2 Правила
- **Топик события** (trigger_topic) — для модулей, которые **рапортуют** данные
- **Топик действия** (action_topic) — для модулей, которые **принимают** команды
- Модуль может иметь оба топика (например button_led: кнопка рапортует, LED принимает)
- Префикс топика **должен точно совпадать** с тем, что указан в коде

### 6.3 Типичные префиксы
| Код | Префикс топика |
|-----|----------------|
| button_led | `button_` / `led_` |
| button_smartLed | `button_` / `smartLed_` |
| button_ledRing | `button_` / `ledRing_` |
| button_swiperLed | `button_` / `swiperLed_` |
| in_2ch | `in_` |
| in_out | `in_` / `out_` |
| out_2ch | `out_` |
| dialer | `dialer_` |
| mp3Player | `player_` |
| hlk2410 | `distanceSens_` |
| pwmLeds | `pwmLeds_` |
| encoderAS5600 | `encoder_` |
| analog | `analog_` |
| stepper | `stepper_` |

### 6.4 Частые ошибки
❌ `radar_0` (старое имя, в коде `distanceSens_0`)
❌ `pwmRGB_0` (старое имя, в коде `pwmLeds_0`)
❌ `smartLed_3/setRGB` в модуле swiperLed (должен быть `swiperLed_3/setRGB`)

## 7. РАЗДЕЛ «ОПЦИИ»

### 7.1 Общий формат описания опции

```markdown
- **имяОпции** - *тип*, описание. Дополнительные детали. По умолчанию {значение}.
```

### 7.2 Типы опций

| Тип в документации | Функция в коде | Пример |
|---|---|---|
| *флаг* | `get_option_flag_val()` | `- **inverse** - *флаг*, инверсия сигнала.` |
| *число(int)* | `get_option_int_val()` | `- **maxBright** - *число*(int), 0-255, макс. яркость. По умолчанию 255.` |
| *число(float)* | `get_option_float_val()` | `- **filterK** - *число*(float), коэффициент фильтрации, от 0 до 1.0. По умолчанию 1.0.` |
| *строка* | `get_option_string_val()` / `get_option_enum_val()` | `- **ledMode** - *строка*, режим анимации.` |

### 7.3 Обязательные атрибуты описания

Для **числовых** опций (int, float):
- Диапазон допустимых значений (если есть ограничения)
- Значение по умолчанию
- Единицы измерения (если применимо)

Для **флагов**:
- Только описание эффекта

Для **строковых** опций:
- Формат строки или перечисление допустимых значений

### 7.4 Формат enum-опций (ledMode, logic и т.п.)

```markdown
- **ledMode** - *строка*, режим анимации:
	- *none* — без анимации (по умолчанию)
	- *flash* — вспышки с равными промежутками времени
	- *glitch* — эффект мерцания
```

### 7.5 Группировка опций
Если модуль имеет несколько функциональных частей, опции группируются:

```markdown
## Опции

Доступные опции для кнопки:
- **buttonInverse** - ...
- **buttonDebounceGap** - ...

Доступные опции для подсветки:
- **ledInverse** - ...
- **fadeTime** - ...
```

Для модулей с единственной функцией:

```markdown
## Опции
Доступные опции:
- **inverse** - ...
- **threshold** - ...
```

### 7.6 Соответствие коду

⚠️ **КРИТИЧЕСКИ ВАЖНО:**
- Имя опции в документации **должно точно совпадать** с именем в `get_option_*_val()`
- Значение по умолчанию **должно совпадать** с аргументом `default` в коде
- Диапазон **должен совпадать** с аргументами `min`/`max` в коде
- Если опция **не читается** из конфигурации (`get_option_*_val` не вызывается), она **не должна быть в документации**
- Если опция **вычисляется** из другой (например `increment` из `fadeTime`), документируется **только исходная** опция

### 7.7 Частые ошибки

❌ Опция `fadeIncrement` в документации — в коде вычисляется из `fadeTime`
❌ Опция `increment` как конфигурационная — в коде значение перезаписывается расчётом
❌ `refreshRate` описан как "в миллисекундах" — это **частота в герцах** (кадров в секунду)
❌ Опция `outImpulse` как конфигурационная — в коде это **команда**
❌ `ledTopic` описан как "топик события" — это **топик действия**

## 8. РАЗДЕЛ «СОБЫТИЯ»

### 8.1 Формат

```markdown
## События
- Описание события. Пример:
	"*moduleBox/topicName_0:значение*"
```

### 8.2 Правила
- Раздел присутствует **только у модулей с входными данными** (кнопки, датчики, энкодеры)
- Каждый тип события — отдельный пункт
- Для каждого события указать: описание, возможные значения, пример

### 8.3 Типичные события

**Кнопка (все button_* модули):**
```markdown
## События
- Рапортует событие при изменении состояния кнопки, возможные значения 0-1. Пример:
	"*moduleBox/button_1:1*"
- При активной опции **longPressTime** рапортует событие длинного нажатия. Пример:
	"*moduleBox/button_1/longPress:1*"
- При активной опции **doubleClickTime** рапортует событие двойного нажатия. Пример:
	"*moduleBox/button_1/doubleClick:1*"
```

**Датчик расстояния (аналоговый + дискретный):**
```markdown
## События
- В аналоговом режиме (threshold = 0) рапортует расстояние, значение в $см$. Пример:
	"*moduleBox/distanceSens_0:156*"
- При включённой опции **floatOutput** рапортует значение в формате float (0.0–1.0). Пример:
	"*moduleBox/distanceSens_0:0.45*"
- В дискретном режиме (threshold > 0) рапортует состояние 0-1. Пример:
	"*moduleBox/distanceSens_0:1*"
```

**Проигрыватель:**
```markdown
## События
- **endOfTrack** - рапортует по окончанию проигрывания трека. В качестве значения передает индекс проигранного трека.
```

### 8.4 Соответствие коду
- Каждый вызов `stdreport_register()` в коде **должен иметь** соответствующее описание в документации
- Подтопик из `stdreport_register()` (например `"longPress"`, `"doubleClick"`, `"endOfTrack"`) отражается в формате примера: `topicName/подтопик:значение`

## 9. РАЗДЕЛ «КОМАНДЫ»

### 9.1 Формат

```markdown
## Команды
- Описание базовой команды.
	- Пример: "*moduleBox/topicName_3:значение*"
- **/имяКоманды** — описание.
	- Пример: "*moduleBox/topicName_3/имяКоманды:значение*"
```

### 9.2 Правила
- Раздел присутствует **только у модулей с исполнительной частью** (LED, выходы, проигрыватель, шаговый двигатель)
- **Базовая команда** (зарегистрированная с `NULL` вместо имени) описывается первой, без слэша
- **Именованные команды** (зарегистрированные с именем) начинаются с `/`
- Для каждой команды: описание, допустимые значения, пример
- Топик в примере **должен совпадать** с action_topic из раздела «Топики»

### 9.3 Соответствие коду
- Каждый вызов `stdcommand_register()` **должен иметь** соответствующее описание
- Если команда зарегистрирована с `PARAMT_none` — она не принимает значений
- Если с `PARAMT_int` — принимает целое число
- Если с `PARAMT_float` — принимает число с плавающей точкой
- Если с `PARAMT_string` — принимает строку

### 9.4 Типичные команды

**LED-модули (button_led, button_smartLed, pwmLeds):**
```markdown
- Меняет состояние подсветки, возможные значения 0-1.
	- Пример: "*moduleBox/led_3:1*"
- **/toggleLedState** — переключает текущее состояние на противоположное.
	- Пример: "*moduleBox/led_3/toggleLedState*"
- **/setRGB** — установка цвета. Строка вида: "ххх ххх ххх".
	- Пример: "*moduleBox/led_3/setRGB:255 0 0*"
- **/setFadeTime** — время нарастания/затухания яркости в миллисекундах.
	- Пример: "*moduleBox/led_3/setFadeTime:500*"
```

**Модули выхода (out_2ch, in_out):**
```markdown
- Меняет состояние выхода, возможные значения 0-1.
	- Пример: "*moduleBox/out_0:1*"
- **/toggle** — переключает состояние на противоположное.
	- Пример: "*moduleBox/out_0/toggle*"
- **/impulse** — формирование импульса заданной длительности в мс.
	- Пример: "*moduleBox/out_0/impulse:500*"
```

### 9.5 Частые ошибки
❌ Команда `setIncrement` в документации — в коде не существует (заменена на `setFadeTime`)
❌ Команда `toggle` описана как значение (`ch_0:toggle`) — в коде это подкоманда (`ch_0/toggle`)
❌ Топик в примере не совпадает с модулем (`smartLed_3` в модуле swiperLed)
❌ Опция описана как команда или наоборот

## 10. РАЗДЕЛ «РЕЖИМЫ АНИМАЦИИ»

### 10.1 Когда используется
Только для модулей с LED-подсветкой, имеющих опцию `ledMode`.

### 10.2 Формат

```markdown
## Режимы анимации:
- **default** - описание режима по умолчанию.
- **flash** - описание режима вспышек.
- **rainbow** - описание режима радуги.
```

### 10.3 Соответствие коду
Список режимов **должен точно совпадать** с перечислением в `get_option_enum_val()`:

```c
// Код:
get_option_enum_val(slot_num, "ledMode", "none", "flash", "glitch", NULL);
// Документация:
// - none, flash, glitch
```

## 11. РАЗДЕЛ «ПРИМЕРЫ»

### 11.1 Формат

````markdown
## Примеры

```ini
[SLOT_n]
mode = имя_модуля
options = опция1:значение, опция2:значение
crosslink = source:значение->target:значение ;комментарий
```
Текстовое пояснение к примеру.
````

### 11.2 Правила
- Используется подсветка синтаксиса `ini`
- Обязательно указать `mode`
- Комментарии через `;`
- После блока кода — текстовое пояснение
- **Все опции в примере должны существовать** в разделе «Опции»
- В конце раздела — ссылка на crossLink:
  ```markdown
  Подробнее об использовании [[Платформа moduleBox/Software#Внутренние связи(crosslink)|crossLink]]
  ```

### 11.3 Частые ошибки
❌ `mode = pwmRGB` — в коде `mode = pwmLeds`
❌ `options = fadeIncrement:5` — опция не существует
❌ `crosslink = radar_3:1->...` — топик не совпадает с кодом

## 15. КОНТРОЛЬНЫЙ СПИСОК ПРОВЕРКИ ДОКУМЕНТАЦИИ

При создании или проверке документации убедитесь:

### Структура
- [ ] Frontmatter содержит title и draft
- [ ] Блок `mode = ...` присутствует и имя совпадает с кодом
- [ ] Все обязательные разделы на месте и в правильном порядке

### Топики
- [ ] Префиксы топиков совпадают с кодом (trigger_topic / action_topic)
- [ ] Топик события — для рапортов, топик действия — для команд
- [ ] Топики в примерах команд/событий совпадают с разделом «Топики»

### Опции
- [ ] Каждая опция из `get_option_*_val()` в коде описана в документации
- [ ] Нет опций, которых нет в коде
- [ ] Имена опций **точно совпадают** с кодом

## 16. ТИПИЧНЫЕ ОШИБКИ И КАК ИХ ИЗБЕЖАТЬ

### 16.1 Устаревшие имена
При переименовании в коде **всегда** обновлять документацию:

| Старое имя | Актуальное имя |
|---|---|
| `radar_` | `distanceSens_` |
| `pwmRGB_` | `pwmLeds_` |
| `fadeIncrement` | `fadeTime` |
| `increment` (как опция) | `fadeTime` (increment вычисляется) |

### 16.2 Опции-призраки
Опции, которые существуют как поля структуры, но **не читаются из конфигурации**:

❌ `inReportDelay` — поле есть, `get_option_*_val` не вызывается
❌ `outDelay` — аналогично
❌ `outImpulse` — это команда, а не опция

### 16.3 Путаница типов топиков
- **Топик события** (trigger_topic) — модуль **отправляет** данные
- **Топик действия** (action_topic) — модуль **принимает** команды
- `ledTopic` / `outTopic` — это **топик действия**, не события

### 16.4 Неверные значения по умолчанию
Всегда проверять значение **в коде**, а не копировать из старой документации:

```c
// Проверяемое место в коде:
ctx->debounce_gap = get_option_int_val(slot_num, "buttonDebounceGap", "", 10, 1, 4096);
//                                                                        ^^
//                                                              значение по умолчанию
```
